class Stock
initialises the stock id — NOT YET FINISHED

Name: initialises the stock name
Border array: Array made up of buy orders. The number of indexes uses this equation: increment of the stock * maxprice + 1. This insures that the lookup is O(1) since the index at a particular pricepoint is price/100
Soffer array: Array made up of Sell offers. The logic is the same as for the border array

class Pricepoint
this class is used to lookup the highest or lowest index of the cheapest or most expensive sell or buy order respectively. Used to find the best offer while filling the orders to insure O(1) THE FIRST TIME. More on this later

class Order
initialises the class order containing:
Order id: initialises the order id — the order id is made of 7 digits: if the first digit or the millionth digit is 1, the order is a buy order, else if the millionth digit is 2 it is a sell order. Otherwise the id is made up of increments of the global counter variable defined below
Price: initialises the price
Quantity: initialises the quantity
MarketOrLimit: initialises the bool value whether the order is a limit or market order
Timestamp: initialises the exact time this order was created and sent into the order book
Stock id: initialises the field that identifies what stock this order is for. It is the same as the class stock id
Portfolio id: initialises the id of the portfolio this order is made for

IDENTICAL HELPER FUNCTIONS
LimitGOrder method — used to process limit sell or buy offers and orders.

bos is a value that takes the first number of the order id that indicates if the order is a sell or buy order. Used to make only one method for filling both buy and sell orders, to make it more readable.

After this, it sets the index as the lowest or highest index for lookup in the Pricepoint class for the cheapest and most expensive sell offer and buy order respectively, to maximise profits. array is set as border (buy order) or soffer (sell offer) according to the bos value.

If there isn't any order (checked using the index — if index is -1, meaning the smallest or largest index doesn't exist, meaning there aren't any orders), it adds the order to the respective queue.
If there is an order, we set the attribute "pricepoint" as the price at which we are happy to fulfil the order (not lower or higher than our ask). We check the buy or sell order again using bos, checking if any sell offers or buy orders satisfy our pricepoint — if they don't, we exit the function and put the order in the respective array again.
If there is an order satisfying our pricepoint:
We walk the array of borders and soffers while any still persist.
Attribute level is the current price level we are at.
If the level is empty, we find the next smallest/biggest index that satisfies our pricepoint and continue.
We do the price check again to insure no price is worse than we want, because we may have advanced further than the condition checked above.
If there is such an element (order), we remove it and try to fill it, using the method "apply_fill" discussed below.
If filled is None, meaning we are trying to sell or buy from ourselves, we break and append the order we tried to fill back.

If filled has two states that indicate an error:
"incoming" = the incoming order's side is at fault → nothing is discarded, matching just stops (break), and both orders survive (resting order goes back, incoming order continues on to be added to the book if it's a limit order).
"element" = the resting order's side is at fault → that resting order is discarded (continue), and the incoming order keeps trying to match against the next price level.

Else, we fill the order.
We recheck if this was the last order — if it was, we move to the next level with findnextsmallest/findnextbiggest again, depending on the bos value.
Last step: if the order didn't get fully filled, add the remainder back to the order queue.

MarketGoOrder method — this method is essentially the same as LimitGOrder, besides removing the safeguards for filling the order at a specific price, filling instead at the best available market price.

Apply_fill method — used in MarketGoOrder and LimitGOrder to fill the order. It checks if we're trading against ourselves, checks how much to return, and checks if we have enough cash/shares to cover the trade.

Settle_trade method — used to assign the stocks and cash to the rightful owner after the sale.

Cancel_order method — used to cancel orders, using a loop to check the border and soffer arrays for the order id we input to determine which order we want to cancel.
